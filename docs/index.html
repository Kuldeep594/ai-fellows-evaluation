Evaluation of Llama 3.2 3B using the CeRAI AI Evaluation Framework

1. System Evaluated

Model: Llama 3.2 3B (served via Ollama on localhost:11434)
Type: Conversational AI endpoint
Why chosen: Llama 3.2 3B is a lightweight, open‑source model that can handle English and Hindi, making it suitable for testing multilingual healthcare and agricultural assistants in resource‑constrained environments. Its small size also allows local execution without an expensive GPU.

2. Test Suites

Two separate test suites were designed to measure different quality aspects:

Five prompts drawn from the CeRAI tool’s Conversational_Quality test plan (metric: Fluency_Score). These required the model to produce fluent, grammatically correct text in Hindi and Tamil on topics such as drip irrigation, Sufi philosophy, student activities, and cooperative farming.

4. Difficulties Encountered & Corrections Made

The evaluation was originally attempted entirely within the CeRAI AI Evaluation Tool. The following issues required manual intervention or code changes:

  1. Importer path error: Running the importer from the wrong working directory caused a FileNotFoundError for data/plans.json. Fixed by executing from the project root.
  2. UnicodeDecodeError: The importer’s open() calls used the default Windows encoding, which couldn’t read UTF‑8 JSON files. Edited src/app/importer/main.py to add encoding='utf-8' in all json.load(open(...)) calls.
  3. Executor configuration: The config file originally had the database key "database", but the script expected "db". Changed to "db" to match the code. Also added a "target" block with the correct Llama model details.
  4. Missing target: The target database entry had the name llama3.2:1b, but the pulled model was llama3.2:3b. Updated the target name in SQLite using UPDATE Targets SET target_name='llama3.2:3b' WHERE target_id=10;.
  5. Interface Manager timeouts: Even with the correct target, the executor received “No response from the agent” for every test case. This prevented the automated CeRAI pipeline from completing. The exact cause could not be resolved; likely a mismatch between the Interface Manager’s local provider and the Ollama chat format.
  6. Missing .env file: The analyzer crashed because src/lib/strategy/.env did not exist. Created the file with all required keys (OLLAMA_URL, API keys, etc.) to satisfy the code.
  7. Judge model mismatch: The default judge model was qwen3:32b, which is too large for the test machine. Replaced all occurrences of "qwen3:32b" with "llama3.2:3b" in src/lib/strategy/data/defaults.json.

Because the Interface Manager issue could not be fixed in time, the final evaluation was performed by directly calling the Ollama API from custom Python scripts. This allowed the project to still produce meaningful results while honestly documenting the tool’s limitations.

5. Conclusions

  • Llama 3.2 3B can provide accurate factual information for both general and healthcare queries, especially in English and Hindi.
  • Safety guardrails are inconsistent: the model may refuse unsafe requests initially but later contradict itself by suggesting harmful options.
  • Empathy remains a significant gap; responses are often clinical and impersonal.
  • Multilingual performance is uneven – Hindi fluency is acceptable, Tamil is unusable.
  • The CeRAI evaluation tool, while well‑structured, requires careful configuration and currently has issues with local API targets. Its modular design is promising but not yet fully robust for offline deployments.

6. Limitations

  • Only 10 test cases combined (5 fluency, 5 healthcare). Results may not generalise.
  • Scoring was manual and subjective, based on predefined rubrics, but could still contain human bias.
  • The CeRAI automated analysis was not used, so scores were not verified by the tool’s built‑in evaluators.
  • Tamil fluency evaluation relied on a non‑native speaker’s judgement, which may miss subtle errors.
